# Domain documentation

This repository uses a single-context layout:
`GLOSSARY.md` at the root and numbered ADRs under `docs/adr/`.

## Before exploring or designing

Read the glossary and ADRs relevant to the area being changed.
If they do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms in proposals, tickets, code, and tests.
When a needed concept is missing, check existing project language
and resolve genuine gaps through domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, citing the ADR
and explaining why it may need revisiting.
